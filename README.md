# $bog_feedback2

Виджет отзывов для приложений на $mol и дашборд к нему. Данные лежат в Гипер Базе,
своего бэкенда нет.

## Как устроено

- **Реестр** — один ленд (`$bog_feedback2_registry`), словарь `feedback_id → ссылка на ленд проекта`.
  Пресет `[null, post('just')]`: ленд нового проекта заводит первый отправитель отзыва,
  заход владельца реестра не нужен.
- **Ленд проекта** — словарь `lord автора → отзыв` (`$bog_feedback2_entry`: текст, контакт, ответ).
- Ленды **не шифруются**: анонимная запись и шифрование в Базе несовместимы
  (`give(null, …)` требует незашифрованного ленда). Всё, что попало в отзыв,
  включая контакт, доступно любому, кто знает ссылку на ленд.

## Виджет

```
<= Feedback $bog_feedback2_form
	feedback_id \myapp
```

`feedback_id` — произвольная строка, ключ проекта в реестре.

**Мастеров синка модуль себе не назначает и список не перебивает** — работает на том
узле, который выбрало приложение. Значит, ленды отзывов должны быть на этом же узле:
мастера между собой не реплицируются. Проверить, что доехало на конкретный узел, можно
дашбордом: `#!master=<url>`.

`?land=<link>` в адресе открывает конкретный ленд мимо реестра — на случай отладки.

## Дашборд

`board/` — отдельное приложение: список проектов из реестра и все отзывы по каждому.
Деплоится на https://b-on-g.github.io/feedback2/

`?registry=<link>` — посмотреть чужой реестр, `#!master=<url>` — прибиться к одному узлу.

Дашборд читает **все** версии указателя на ленд проекта, а не только победившую.
Если ленд когда-то форкнулся (второй посетитель не дождался реестра с мастера и завёл
свой), отзывы из обеих веток всё равно видны.
